# Prototype state and data lifecycle

All new files are local in Fair_to_Forget_Multigroup_20260926, outside iCloud. No dataset, environment, Git metadata, archive, model checkpoint or live manuscript was copied into Documents. Local-only files need a separately chosen backup.

- Read-only data inputs are the existing ACS standardized and encoded arrays, population/native-row metadata, legacy sex labels and frozen transform under Fair_to_Forget_Dtype_Repair_20260919/remediation/p3/data/acs2018-ftf1-p3-v1. No new population is sampled. The full Census CSVs are not re-read or restored; documented numeric RAC1P codes are decoded from unquantized standardized values with exact forward equality and frozen provenance.
- Each worker holds its processed input views, new categorical membership array, original model and resident DIRECT state. State contains represented float coordinates, encoded integer coordinates, group arrays, persistent IDs, per-client/group counts, summaries and config/seed. Arrays are read-only by convention. Every whole-client request is independent against that original state.
- DIRECT reuses surviving summary objects and resident coordinate/encoded/group views. Dropping a client dictionary entry is not deletion of the backing buffer, previous state or experiment input. Positive rounds recompute all retained assignments/moments. No old assignment certificates or per-point distance cache is maintained.
- Compact T0 state copies small summary arrays and marks them non-writable; it retains original client IDs (including empty clients), exact per-group counts, local selected slice indices, representatives, anchors, multiplicities, config and seed. A new compact state after deletion shares surviving summaries. Nested dictionaries are trusted and mutable; this is not a hostile-state validation or authenticated storage API.
- Compact anchors/representatives can equal individual rows, especially at zero quantization. Selected indices and counts also retain information. Previous states/models and all original data remain. No privacy, secure aggregation, physical purge or erasure claim is made.
- Outputs saved on disk are exact model trajectories/moments, gate summary/solver/quality evidence, compact timing observations, logs, tables, source and reports. Large original state/checkpoint pickles are never persisted by this task. Pickle sizes in tables are measured by serializing in memory and discarding the bytes; they are not measured RAM or disk savings.
- Request timing includes model witness serialization and a local write without fsync; it excludes state persistence, durable recovery, loading, setup, quality scoring, verification, process startup, network and secure erasure. A deployed service with those obligations needs a new cost study.

No actual disk savings are claimed. The original binary T0 candidate/review and frozen experiments remain immutable and are not replaced by this variant.
