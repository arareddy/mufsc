## Measured boundaries
Algorithm seconds: perf_counter around full train_full(build_cache=False) or unlearn call, including validation, internal encoding/materialization, allocations, primitive timing and witness-ready numerical results. Fresh does not construct replay point caches.

Primary E2E request seconds: contiguous elapsed wall time from opening frozen input bundle through retained-input materialization (same work for every method), loading budget-matched checkpoint for replay, explicit pre-call GC, algorithm call, construction of full exact numerical witness, and equal-schema JSON witness serialization/write. Input bundle contains original population and deletion batch; request parsing and retained allocation are charged symmetrically. Quality scoring, result verification, reporting metadata/receipt writes and checkpoint setup are outside this boundary and separately observed. Witness creation and GC are explicit additions to the corrected September19 E2E sum. Input hashing/source gate checks occur before request timing. Full source/bundle load remains warm-OS-cache, separate-process measurement. Input preprocessing and initial environment/import startup are not request costs. A separate process-startup-inclusive view adds parent-launch-to-worker-ready time; it is not network latency.

Offline setup: build and persist a separate original-population checkpoint for every T, with input loading, cache-enabled algorithm and serialization times and bytes. Never charge this to Fresh request latency. No serialized replay output is claimed reusable as a subsequent checkpoint. Quality is the exact maximum of group-average nearest-center squared distances on fixed-point retained records; evaluate gate outputs and associate identical repeated witnesses with the exact gate score. Repeated quality evaluation is unnecessary for measured calls.

Primitive client/server, encoding, materialization, certificate, failed-assignment and fallback timers are retained. Nested timers overlap and must not be added as disjoint totals. Uninstrumented algorithm overhead is algorithm elapsed minus disjoint encoding/input/cache/client/server timers, where applicable. Ideal parallel-client estimate is existing sum of per-round max-client times plus server totals; excludes untimed overhead and all communication, and is kept separate from measured serial wall time. C0 still requires client summary/group-count communication and server initialization; no transport is measured.
