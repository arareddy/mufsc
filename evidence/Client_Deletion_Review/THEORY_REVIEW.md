# Whole-client deletion at C0: independent correctness and scope review

26 September 2026. Run `client-review-20260926T064407Z`.

**Conclusion.** Whole-client deletion by dropping that client's group summaries, updating exact global group counts, reconstructing the canonical weighted anchor table, and rerunning the server is exactly equivalent to fresh **T=0** FTF-1D training with the same seed and retained persistent IDs. This is equality of the indexed released C0/final model, conditional on the fixed preprocessing, numerical map and configuration. Surviving local summaries need no retraining. This result does not itself promise a speed factor, erase the original checkpoint, or preserve the old server centers. It is the initialization part of the existing replay theorem specialized to a simpler request class, not a new general unlearning theorem.

The independently written scalar oracle passed all 196 valid tiny deletion configurations against the frozen implementation. Those finite checks support the implementation reading; the functional argument below establishes the scoped proposition. Task B's immutable v1 also passed snapshot-specific independent checks; its exact scope and identity are in IMPLEMENTATION_REVIEW.md and REVIEW_READY.json.

## 2. Sufficient summary and precise assumptions

Write the represented group slice as the ordered sequence X[c,g]. Its local function is

`H[c,g] = Local(X[c,g]; seed, role=local, persistent_client_id=c, group_id=g, k, gamma)`.

A nonempty local summary contains ordered selected slice indices, unsnapped representatives, snapped anchors, integer multiplicities h, k_e=min(k,n_cg), and n_cg. Multiplicities assign to the **unsnapped** indexed representatives. For output-only replay, anchors, h, stable owners and a dimension/configuration binding suffice; original representatives/selected indices are helpful evidence but are not required by server sampling. Exact per-client/group counts can either be retained explicitly or recovered as sum_j h[c,g,j]. An empty client's identity must be retained in a client registry if deleting such a client is a valid API operation; it has no summary from which to infer its existence.

The sufficient assumptions are:

1. **Fixed represented data.** Preprocessing, feature columns, scaling, clipping and fine-grid parameters are fixed. Surviving binary64 represented rows and group memberships do not change. Refitting a transform after deletion defines a different target. A gamma chosen from original n is frozen; recomputing gamma from survivor n changes the local quantization map.
2. **Stable identity and sequence.** Retained client IDs and group labels are unchanged; each surviving slice keeps its row order. Server owners are ordered lexicographically (client,group,slot), preserving slot identity even for coincident locations or zero multiplicity. Removing a client may leave gaps in IDs; compacting IDs is not an innocuous optimization.
3. **Reproducible entity streams.** The local seed key is `[seed,1,c,g]`, and the server key is `[seed,2]`. A fresh stream is initialized per entity. Deleting a client cannot shift another entity's draw position. A shared sequential generator, a reindexed client seed, changed NumPy stream semantics, or continuation from the old server's exhausted state does not meet this condition. Mathematical stream independence is unnecessary for pointwise same-seed equality; independence of ideal tapes is a separate assumption used by approximation statements. Finite PCG64 key separation is not a proof of ideal independence.
4. **Local-only dependence.** The existing split-group local sampler uses unit weights, then within-slice squared distances. It does not read global n_A/n_B. Both its local assignment and snapping depend only on the same slice/configuration. A locally balanced merged sampler using 1/n_cg is also unchanged by deletion of *other whole clients*. Thus this reuse property is not unique to group separation; the fair approximation and local/global weighting arguments are separate.
5. **Exact current server input.** Dropped owners are removed; current n'_g is the exact sum of retained slice counts, and each survivor anchor is assigned the exact rational h/n'_g. Rebuild the same list and rerun the fresh server sampler with its initial stream and fixed optional anchor-Lloyd count. Cached old weights and old server centers are insufficient in general.
6. **Same numerical conventions.** Use the declared rational categorical sampler, binary64 representation, exact tie comparisons, smallest-index winner, saturation and zero-potential completion, snapping, and optional guarded weighted anchor Lloyd. The theorem holds for supported valid inputs and the same terminating execution; it does not waive input validation or arithmetic domain restrictions.
7. **Valid request.** The request is a set of known whole-client IDs, without duplicates or malformed IDs, and both global protected groups remain nonempty. Empty local slices are omitted. k, T=0, gamma, fine-grid parameters, seed and optional server iteration count agree with the fresh reference.

Global normalization inside a local sampler deserves a precise qualification. Multiplying *all* weights in a single separated slice by the same positive rational 1/n_g cancels from the categorical probabilities and, under the exact lcm/gcd sampler, from the primitive integer mass vector; it need not change that local map. The failure is unequal changed factors in a mixed-group local call (or noncanonical floating rounding/global-dependent branches). For an untouched mixed client with one A and one B row, changing global counts from (2,1) to (1,1) changes a globally weighted first-draw probability for its A row from 1/3 to 1/2. Summary reuse then lacks its premise. The implemented local unit weights avoid this dependence.

## 3. Proposition and proof

**Proposition (whole-client summary replay at T=0).** Fix a valid represented dataset X partitioned by persistent clients and binary groups, a supported FTF-1D configuration theta with T=0, and a seed s. Let H[c,g] be the local summaries produced on X. Let D be a set of whole clients for which n'_A,n'_B>0. Form H' by deleting all entries whose client lies in D; compute n'_g from exact retained counts; rebuild the canonical table `(c,g,j,q[c,g,j],h[c,g,j]/n'_g)`; and run the declared server procedure from its fresh stream with the original parameters. Under the assumptions in Section 2, the resulting indexed tuple is exactly `C0(Train_theta(X without D; s))`. The retained summaries, group counts and canonical anchor table also equal their fresh mathematical counterparts.

**Proof.** For every retained nonempty (c,g), whole-client deletion leaves its ordered represented slice, configuration and keyed stream unchanged. Local seeding is therefore the same deterministic computation. It selects the same indexed rows, makes the same tie-broken assignments, produces the same integer multiplicities, and snaps the same representatives. Deleted slices have no fresh counterpart; surviving empty slices are omitted in both procedures. Each retained point contributes exactly once to the corresponding multiplicity sum, including coincident representatives whose higher indexed slots may have zero multiplicity, so the reconstructed n'_g equals the fresh group count. Consequently each anchor, owner, rational weight and list position equals fresh training's input to the server. Resetting the same server key yields the same integer masses, random words/rejections and selected indices; deterministic completion covers zero potential and too few anchors. Any fixed optional weighted anchor-Lloyd iterations see the same inputs and guards and thus return identical represented centers. Since T=0, this tuple is the entire released trajectory and final model. No record-level Phase-II statistics or induction is needed. QED.

An empty original client can be retained as an empty client or omitted after its own valid deletion without changing C0; complete metadata dictionaries may then differ. No claim of dictionary equality is part of the proposition.

**Distributional corollary and limits.** For every fixed or seed-independent D, pointwise equality in s implies equality in distribution for any seed law, including the actual finite-seed implementation. Under independent ideal entity tapes the analogous result holds for the ideal learner. This is neither a claim that PCG64 implements ideal randomness nor a fresh-independent claim for D chosen adaptively from the same seed-dependent checkpoint. The pointwise identity still applies to each realized valid (s,D), but conditioning on such a D can change the distribution of s relative to a new independent retraining seed. Full original caches/raw arrays, RNG bookkeeping, timing fields, historical logs and deletion traces need not equal fresh state and may still contain deleted data. A compact *mathematical projection* (surviving local summaries, current counts/table) can equal fresh; storage erasure or a sequential service needs a separate specification. IMPLEMENTATION_REVIEW.md establishes the candidate's narrowly specified compact-state sequence invariant, not a general erasing service.

## 4. Concrete boundaries and counterexamples

The machine-readable examples are in `results/fixtures_initial.json`, key `details.assumption_counterexamples`.

- **Client renumbering:** seed 0, group 0, points `(0,1,2,3,4,5)`, k=2. The independent oracle with persistent client ID 42 selects slice indices `(1,5)`; renumbering it to 0 selects `(5,0)`. Reusing the ID-42 summary cannot represent the ID-0 retraining map. The fixture also covers gaps 2,42,105,1001 in complete server tests.
- **Row reordering:** on the same six points, seed 0, ID 42, k=1, the selected location is 1 in ascending row order and 4 in reversed order. Stable location sets alone are insufficient for the fixed-seed indexed map.
- **Refitted transform:** raw values (0,0,10) have mean 10/3. If a deleted client owns 10, surviving zero rows change from -10/3 to 0 when standardization is refitted (fine-grid b=2 maps these to -3.25 and 0). The fixed-data premise has failed.
- **Stale denominators:** one deleted pure-A client plus a surviving pure-A anchor and a pure-B anchor gives pre-deletion n=(2,1), post-deletion n'=(1,1). Retained weights must be (1,1); keeping the old denominators gives (1/2,1), changing first-anchor probabilities from (1/2,1/2) to (1/3,2/3). Even perfect surviving anchors do not justify keeping old weights or server output.
- **A whole global group disappears:** deleting the only B client makes Phi_B and h/n'_B undefined. The current train/replay map rejects the request. Silently switching to active groups is a new learner, not an extension established here.
- **Deleting records within a survivor:** even when no selected representative is deleted, h and n_cg change. In the tiny seed-0, ID-42, k=1 slice (0,1,2,3), representative index 1 is selected. Deleting nonselected row 0 reduces the only multiplicity from 4 to 3. Reusing the complete old summary is wrong; fixed-seed reseeding can also change the representative because the integer masses and random-word consumption change. Whole-client deletion has no retained touched slice and avoids this problem entirely.

Repeated locations, zero weights and saturation are not informal exceptions. A tied point is assigned to the first indexed representative, possibly leaving another representative's multiplicity zero. The declared completion may subsequently include zero-weight rows or cyclic repeats. Sorting/deduplicating anchors by coordinate, dropping all zero slots, switching to sampling without replacement in saturated cases, or changing the tie rule needs its own equivalence proof. Our positive-gamma fixture checks that assignment precedes snapping and that the same snapped output is used on both paths.

**Weights and attribution.** Pan's local sampler is ordinary unweighted k-means++ initialization; it is not our locally demographic-balanced MERGED-1K with local weights 1/n_cg. Our merged construction is an adaptation and its heterogeneity theorem must not be attributed to Pan's learner. Pan's multiplicities are cluster-size weights, without the current protected-group h/n_g normalization.

**Record-deletion gap does not invalidate the whole-client argument.** Algorithm 4 line 3 updates q^(l) only when local retraining occurs, while Algorithm 1 defines q from cluster counts. A removed nonselected record still changes a count. The prior investigation documents the public code's whole-local-restart-on-hit and stale-server-on-miss branches at pinned commit `be95c75167547aa21556a9feaeed60a0afa59854`; those code observations are attributed to that preserved investigation here, not newly re-executed or presented as the known experiment-time commit. Rebuilding counts and the server is therefore necessary to transfer a local result to a fresh-equivalent global map. Whole-client deletion removes the entire contribution and reruns the server, so the local-miss count gap is not an obstacle to the proposition in Section 3.

**What the speed numbers compare.** The primary paper states full local-and-global retraining as its comparator and uses a max-client-plus-server timing model. The preserved code investigation identifies an initial hybrid full-Lloyd retraining proxy, reused across the sequence, and a resident-state deletion timer with a skipped-server miss path. These are materially different from actual retained-data T=0 retraining with equal output scope. Figure 3's rounded random-removal legends are 21,44,30,43,164,6,27x (simple mean 335/7, about 47.9x), while the text reports 84x; without the aggregation/raw runs neither aggregate can be reconstructed here. Table 1's conditional no-retraining values are not all-request speedups. No direct numerical cross-paper comparison is justified.

## 6. Why record-prefix repair is a separate algorithm

For a fixed removed set and an ordinary ideal categorical sampler, conditioning a candidate not to be removed renormalizes its probability onto survivors. Keeping the prefix before the first hit and regenerating the suffix can exploit that coupling; restarting the *whole* local sampler only on a hit is different and biased in general.

Our independent Fraction enumeration on {0,1,2,3}, k=2, delete 3 reproduces the complete ordered fresh law under prefix repair. Fresh probability of the unordered set {0,1} is 7/30. Keeping original no-hit outcomes but doing whole restart on hits gives 257/1260, which is unequal. This is an exact finite counterexample, not a frequency test.

Even that ideal prefix mechanism cannot be inserted into the present fixed-seed indexed learner unchanged. On {0,1,2}, k=2, delete 2, fresh FTF saturation deterministically returns ordered indices (0,1). A naive original-prefix repair returns (1,0) with probability 1/3 and (0,1) with probability 2/3. The unordered set agrees, but the declared indexed distribution does not. Finite PCG64 streams and rejection sampling add a further seed-to-output coupling obligation. A direct original/fresh same-seed equality requirement ordinarily needs replaying the touched slice, unless a separately proved mechanism reconstructs precisely the fresh choices.

A future record repair would need to specify the indexed law and saturation/zero-potential rules, maintain source IDs and local assignment/multiplicity state, handle missing representatives and changed local masses, update both global denominators, rebuild the server, and prove its chosen finite or ideal coupling. If T>0 it must also reproduce raw-data fair refinement. No such variant is implemented or approved here.

## 7. Cost decomposition and necessary conditions for 10x

Let n' be retained records, C' retained clients, and m'=sum_(c,g) min(k,n_cg) <= 2 C' k retained anchor slots (zero-mass slots included). A compact client-deletion cache can retain O(m'd+C') coordinate/count words, plus model/configuration/identity provenance; rational/integer bit lengths and object/serialization overhead are additional. No n'T point cache is required at T=0. Preparation still reads and summarizes the original data once.

For a **matched fresh T=0 baseline**, write its elapsed cost as

`F = data_access_F + validation_F + encoding_F + local_summaries_F + table_F + server_F + output_F`.

Write the client-deletion request cost as

`U = cache_access_U + request_validation_U + count/summary_maintenance_U + table_U + server_U + output_U`.

If a wrapper loads/materializes retained raw arrays, scans group arrays, re-encodes points, evaluates raw-data quality, constructs a full fresh checkpoint, or serializes raw arrays, those costs belong in the relevant path, even if outside an inner algorithm timer. Count maintenance can subtract cached per-client counts in O(|D|) for two groups; a simple implementation may instead traverse O(C') summary metadata. Filtering and canonicalizing the compact table take O(m'd+C' log C') unit work. Neither requires scanning surviving raw records.

Server k-means++ on the compact table still performs roughly O(k m' d) geometry work plus exact categorical mass/gcd and RNG work. Optional anchor Lloyd adds assignment, weighted means and guards over m' anchors per iteration; the current label-only wrapper internally calls the general assignment routine and sorts candidate centers. Arbitrary-precision rational arithmetic, bit lengths, degeneracies and actual NumPy/Python overhead prevent turning these unit-operation bounds into elapsed-time guarantees. There is no free constant-time server update proved here.

The old `unlearn()` public call is *not* this compact-access implementation. It constructs full retained/removed masks and arrays, scans group labels in `_phase1_rewind_or_skip`, and calls `_retained_views` even at T=0; those are implementation costs, not a mathematical consequence of fairness. The manuscript already discloses this W0 term. A client-only API can avoid these scans by validating whole-client IDs and using sufficient counts.

For 10x at the same boundary, necessarily **F >= 10 U**. If shared irreducible costs total B, saved local work is L and added request overhead is delta, with F=B+L and U=B+delta, then **L >= 9B + 10delta** is necessary and sufficient in this model. If residual server+I/O+output alone exceeds F/10, 10x is impossible for that case under those boundaries. With additional cache preparation cost H amortized over Q requests, require **F >= 10(U+H/Q)**; when F>10U this means Q >= 10H/(F-10U), using the actual matched sequence of request costs if they vary. State original-training cost and the *incremental* cache-preparation cost separately, since some deployments already need initial training but this does not make extra cache work free.

A favorable opportunity requires raw-local initialization to dominate fresh cost, compact cache access, correct cheap counts, a relatively small anchor table, a bounded server procedure, sufficient cache amortization, and matched model output. It remains conditional until measured on the declared cases with all losses retained. Dropping T from 15 or 5 to zero changes the learner and utility tradeoff; original-T fresh divided by T=0 replay is not a same-map unlearning speed factor. Neither Pan's 84x nor the existing repaired FTF timings supplies a 10x guarantee for this candidate.
